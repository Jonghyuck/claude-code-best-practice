# Day 1 — Your First Conversation with Claude Code

[Back to Day 0 (Setup)](../day0/README.md)

---

Claude Code를 설치했습니다. 이제 무엇을 해야 할까요? 이 가이드는 Claude Code를 사용하는 세 가지 단계를 안내합니다 — 각 단계는 Claude가 작업을 **어떻게** 수행하는지에 대해 더 많은 통제권을 제공합니다.

누군가를 고용하는 것에 비유해 보세요:
1. **프롬프팅(Prompting)** = 길에서 낯선 사람에게 길을 묻는 것
2. **에이전트(Agents)** = 항상 특정 방식으로 일을 처리하는 전문가를 고용하는 것
3. **스킬(Skills)** = 그 전문가가 특정 작업을 위한 구체적인 훈련을 받은 것

---

## Level 1: Prompting (Just Ask)

> 🧠 **이렇게 생각해 보세요** 아는 것이 많은 친구에게 문자를 보내는 것과 같습니다. "카라치 날씨가 어때?"라고 물으면 친구는 *어떤* 답을 주긴 하지만 — 날씨 앱을 확인했는지, 창밖을 내다봤는지, 아니면 그냥 기억에 의존해 추측한 것인지 알 수 없습니다.

터미널을 열고 `claude`를 입력하세요. 이제 대화가 시작됩니다. 다음을 입력해 보세요:

```
what is the weather in Karachi?
```

Claude가 답을 하겠지만 — **어떻게** 답하는지는 예측할 수 없습니다. 다음과 같을 수 있습니다:
- 학습 데이터에서 가져오기 (오래된 정보일 수 있음)
- 웹 검색 (웹 도구를 사용할 수 있는 경우)
- 실시간 데이터 대신 일반적인 답변 제공

간단한 질문에는 전혀 문제가 없습니다! 하지만 **일관되고 신뢰할 수 있는 결과**가 필요하다면 프롬프팅만으로는 충분하지 않습니다.

### When Prompting Works Great

- 코드베이스에 대한 질문 ("이 파일은 무엇을 하나요?")
- 문서 작성 또는 편집 ("이 이메일을 더 전문적으로 들리게 다시 써 주세요")
- 아이디어 브레인스토밍 ("이 캠페인을 위한 제목 5개를 제안해 주세요")
- 설명 요청 ("이 오류 메시지를 개발자가 아닌 사람도 이해하도록 설명해 주세요")

### The Limitation

"날씨가 어때?"라고 물을 때마다 Claude는 데이터를 다르게 가져올 수 있습니다 — 혹은 실제 데이터를 아예 가져오지 않을 수도 있습니다. 같은 출처나 방법을 두 번 사용한다는 보장이 없습니다.

## Level 2: Agents (The Specialist)

**에이전트**는 특정 역할을 수행하는 Claude입니다 — 직책을 부여하는 것과 같습니다.

> 🧠 **이렇게 생각해 보세요** 레스토랑 주방과 같습니다. 에이전트가 없으면, 아무 주방에나 들어가 "파스타 만들어 줘!"라고 외치는 것과 같습니다 — 그 말을 들은 사람이 인스턴트 라면을 끓일 수도, 5코스 이탈리안 요리를 만들 수도 있습니다. 에이전트가 있으면, *"항상 신선한 재료를 쓰고, 항상 알 덴테로 익히고, 항상 같은 방식으로 담아낸다"*는 직무 기술서를 가진 **파스타 셰프**를 고용하는 것입니다. 이제 매번 정확히 무엇을 얻게 될지 알 수 있습니다.

같은 아이디어를 Claude에 적용하면 다음과 같습니다:

> **에이전트 없이:** Claude에게 "두바이 날씨가 어때?"라고 묻습니다.
> Claude는 학습 데이터를 확인하거나, 웹을 검색하거나, 최선의 추측을 할 수 있습니다. 무엇을 할지 알 수 없습니다.
>
> **에이전트와 함께:** `weather-agent`는 명확한 직무 기술서를 가지고 있습니다:
> *"항상 두바이에 대해 Open-Meteo API를 확인한다. 항상 특정 형식으로 온도를 반환한다."*
> 같은 질문, 같은 접근 방식, 매번 동일합니다.

### Real Example from This Repo

이 저장소에는 `weather-agent`가 있습니다 — 이 에이전트의 전체 임무는 두바이의 온도를 가져오는 것입니다. 단순한 프롬프팅과 다른 점은 다음과 같습니다:

| | Prompting | Agent |
|---|---|---|
| **Source** | 어디든 될 수 있음 | 항상 Open-Meteo API |
| **Location** | Claude가 고르는 대로 | 항상 두바이 (lat: 25.2, lon: 55.3) |
| **Format** | 임의의 문단 | 깔끔한 온도 + 단위 |
| **Consistency** | 매번 다름 | 매번 같은 방법 |

### The Takeaway

에이전트는 **예측 가능성**을 제공합니다. 같은 질문 → 같은 접근 방식 → 같은 품질. 그것이 바로 장점입니다 — 에이전트가 더 똑똑해서가 아니라 **일관되기** 때문입니다.

## Level 3: Skills (The Training)

**스킬**은 에이전트(또는 Claude 자체)가 사용할 수 있는 특정 역량입니다.

> 🧠 **이렇게 생각해 보세요** 신입 직원의 교육 매뉴얼과 같습니다. 누군가 팀에 합류하면 역할(에이전트)을 갖지만, CRM 사용법, 제안서 작성법, 스탠드업 진행법 같은 구체적인 교육 모듈도 거칩니다. 각 교육 모듈이 하나의 **스킬**입니다. 역할은 그들이 *무엇*인지 알려주고, 스킬은 특정 일을 *어떻게* 하는지 알려줍니다.

이제 실제 사람을 생각해 보세요:

> **Shayan**은 여러 스킬을 가지고 있습니다:
> - 엔지니어링 스킬 — 코드를 작성할 수 있음
> - 게임 스킬 — 게임 메커니즘을 앎
> - 독해 스킬 — 긴 문서를 소화하고 요약할 수 있음
>
> 각 스킬은 고유한 지식과 방법을 가지고 있습니다. Shayan은 적절한 작업에 적절한 스킬을 사용합니다.

Claude도 같은 방식으로 작동합니다. `weather-agent`에는 `weather-fetcher`라는 스킬이 있습니다:

- **에이전트**(`weather-agent`) = "기상 리포터"라는 직책을 가진 사람
- **스킬**(`weather-fetcher`) = 날씨 데이터를 *어떻게* 가져오는지에 대한 구체적인 훈련

스킬에는 정확한 지침이 담겨 있습니다:
1. 이 특정 API URL을 호출한다
2. 응답의 이 특정 필드에서 온도를 추출한다
3. 이 특정 형식으로 반환한다

### Why Separate Agents and Skills?

**하나의 에이전트가 여러 스킬을 가질 수 있고**, **하나의 스킬을 여러 에이전트가 사용할 수 있기** 때문입니다.

예를 들어, 다음을 만든다고 상상해 보세요:
- 하루를 요약해 주는 `daily-report-agent`
- 이 에이전트는 `weather-fetcher` 스킬(날씨용) + `calendar-reader` 스킬(회의용) + `email-summarizer` 스킬(이메일 주요 내용용)을 사용할 수 있습니다

스킬은 재사용 가능한 빌딩 블록입니다. 에이전트는 그것을 사용하는 사람입니다.

## Putting It All Together

전체 그림은 다음과 같습니다:

```
Level 1: PROMPTING
You → "What's the weather?" → Claude figures it out somehow
                                (unpredictable method)

Level 2: AGENTS
You → Weather Agent → Always uses the same approach
                      (predictable method)

Level 3: SKILLS
You → Weather Agent → Uses weather-fetcher skill
                      (predictable method with specific instructions)
```

각 단계는 더 많은 통제권을 더합니다:

| Level | What You Control | Best For |
|-------|-----------------|----------|
| **Prompting** | 질문 | 빠른 일회성 질문 |
| **Agents** | 질문 + 누가 답하는지 | 반복 가능한 작업 |
| **Skills** | 질문 + 누가 답하는지 + 어떻게 하는지 | 핵심 워크플로우 |
